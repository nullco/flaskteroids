Forms

A form has two parts: the template that builds inputs, and the controller that accepts their values. Use form_with to build the form and self.params.expect to choose which submitted attributes may reach your model.

After reading this guide, you will know how to:

  • Build a model-backed form and choose its fields.
  • Permit submitted attributes and redisplay invalid input.
  • Edit associated records with nested forms.

Building forms

Pass a model to form_with. It chooses the destination and HTTP method, supplies field values, and includes a CSRF token. Inside the block, use form to create labels and inputs:

<!-- app/views/posts/_form.html -->
{% call(form) form_with(model=post) %}
  <div>
    {{ form.label("title") }}
    {{ form.text_field("title") }}
  </div>

  <div>
    {{ form.label("content") }}
    {{ form.text_area("content") }}
  </div>

  <div>
    {{ form.submit("Save") }}
  </div>
{% endcall %}

Destinations and HTTP methods

For a conventional Post resource:

Model state Destination Method
New record /posts POST
Saved record /posts/<id> PATCH

Browsers submit PATCH as POST with a hidden _method field. Set method to override the default; method="PUT" also works for updates.

An explicit URL changes only the destination. The model still supplies values, errors, and default method inference:

{% call(form) form_with(model=post, url="/review", method="POST") %}
  {{ form.text_field("title") }}
  {{ form.submit("Review") }}
{% endcall %}

With a persisted post, omitting method="POST" here would infer PATCH, not POST. Ordinary nested model destinations accept a list or tuple:

{% call(form) form_with(model=[product, subscriber]) %}
  {{ form.email_field("email") }}
  {{ form.submit("Subscribe") }}
{% endcall %}

A new child submits to product_subscribers_path(product) with POST; a persisted child submits to product_subscriber_path(product, subscriber) with PATCH. Fields use the child prefix (subscriber[email]) and child values, including rejected input. scope="signup" overrides that prefix without changing the model that supplies values and errors. A missing parent identifier raises an error. Nested URLs do not automatically save nested model attributes.

Turbo and HTML attributes

Pass HTML attributes directly to form_with, including nested data and aria dictionaries. class_ emits class; nested keys become dashed attributes:

{% call(form) form_with(model=post, class_="editor", data={"turbo_frame": dom_id(post)}) %}
  {{ form.text_field("title") }}
  {{ form.submit("Save") }}
{% endcall %}

Use data={"turbo_frame": "_top"} to navigate outside a frame, data={"turbo": False} to submit without Turbo, or data={"turbo_stream": True} to request Streams on a GET form. For Turbo validation failures, render HTML with 422; redirect successful mutations with 303 See Other. See the inline edit example and HTTP Streams.

Choose a field helper

Field helpers include text_field, text_area, password_field, and checkbox. Use file_field('avatar') or file_field('documents', multiple=True) for uploads. form_with detects these fields and adds multipart encoding. See Attachments for attachment forms and permitted parameters.

Use form.rich_text_area("content") for declared rich-text attributes. Install Lexxy and storage with bin/flask rich_text:install, then migrate. See Rich text for setup, rendering, and validation.

Strong parameters

Strong parameters are an allowlist of attributes a controller may pass to a model. Use self.params.expect for this filtering. Do not pass unfiltered request data to create or update: users could change fields you did not intend to expose, such as an admin flag.

expect also checks the input's structure, including nested objects and lists. For a post form:

# app/controllers/posts_controller.py
from app.models.post import Post
from flaskteroids.controller import Controller
from flaskteroids.routes import post_path


class PostsController(Controller):
    # ...

    def create(self):
        self.post = Post.new(**self._post_params())
        if self.post.save():
            return self.redirect_to(post_path(self.post), status=303)
        return self.render("new", status=422)

    def update(self):
        self.post = Post.find(self.params["id"])
        if self.post.update(**self._post_params()):
            return self.redirect_to(post_path(self.post), status=303)
        return self.render("edit", status=422)

    def _post_params(self):
        # Assumes form data is sent as:
        # post[title]=...
        # post[content]=...
        return self.params.expect(post=["title", "content"])

self.params.expect(post=["title", "content"]) requires a top-level post dictionary, but its nested fields are permitted, not required. It returns only submitted, permitted attributes and discards other attributes. The same allowlist works for both creation and partial updates:

# Submitted: post[content]=Updated
attributes = self.params.expect(post=["title", "content"])
# attributes == {"content": "Updated"}
post.update(**attributes)  # The existing title is unchanged.

This also applies recursively to nested dictionaries and arrays of dictionaries. Omitted fields are not filled with defaults; an explicitly submitted None scalar is retained. Use model validations to require attributes, rather than treating the allowlist as validation.

JSON-valued fields

Use the explicit JSONValue schema marker for a field that accepts an entire JSON value, such as a JSON database column:

from flaskteroids.actions import JSONValue

attributes = self.params.expect(post=["title", ("settings", JSONValue)])

This permits objects with arbitrary string keys, arrays, strings, finite numbers, booleans, and null, including nested values and empty containers. The permission is limited to settings: other attributes still need their own allowlist entries. Uploads and arbitrary Python objects are rejected. Prefer an explicit nested schema when the permitted keys are known; JSONValue deliberately permits all JSON content inside that one field.

Scaffold generators use this schema automatically for name:json columns. Omitting the field leaves it unchanged during partial updates. JSON strings are values, not an invitation to decode another JSON document inside them.

Missing or malformed input

  • A missing, null, or empty root raises MissingParameter. This includes a dictionary with no permitted attributes left after filtering.
  • A required scalar root such as self.params.expect("password") rejects blank strings, but accepts False and numeric zero.
  • An incorrect type raises InvalidParameter. Optional fields must still have the expected structure when submitted.

During HTTP requests, Flaskteroids automatically translates MissingParameter and InvalidParameter into 400 Bad Request responses; controllers do not need to catch them. Browser controllers return an HTML error page, including when JSON is requested; API controllers return JSON errors. Applications can customize either response with Flask's register_error_handler() in an initializer (for example, to return JSON). Direct calls outside request dispatch still raise these exceptions. Programmer errors and unrelated exceptions are not translated into 400 responses.

Redisplay validation errors

When saving fails, render the form with the submitted model and status 422. Do not redirect or load a fresh copy: the submitted object holds the values and errors the user needs to correct.

Add error messages to the form partial before its fields:

{% for message in post.errors.full_messages() %}
  <p role="alert">{{ message }}</p>
{% endfor %}

Fields show the original input, even when type conversion failed. Passwords must be entered again after a failed submission.

CSRF protection

Cross-site request forgery (CSRF) is an attempt to make someone's browser submit an unwanted request while they are logged in. A session-bound token helps the server verify that a form came from your application.

Flaskteroids checks CSRF tokens on state-changing requests, meaning all methods except GET, HEAD, OPTIONS, and TRACE. form_with and button_to include the token for unsafe forms, never GET forms. An overridden DELETE receives the same protection as an actual DELETE request. See Routing.

Tokens belong to the browser session and expire after one hour. Clearing the session invalidates its tokens; reload forms to obtain a new token. AJAX requests can send the token in the X-CSRF-TOKEN header instead of the csrf_token form field. Generated layouts also include <meta name="csrf-token" content="{{ csrf_token() }}"> for Turbo's request header. Add it to custom layouts when installing Turbo. Do not store pages containing CSRF tokens in a shared cache.

Include the token yourself in manual forms:

<form action="/posts" method="post">
  <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">
  <!-- ... form fields -->
</form>

Buttons that submit forms

{{ button_to("Create", "/products") }}
{{ button_to("Save", product) }}
{{ button_to("Delete", product, method="DELETE") }}
{{ button_to("Log out", session_path(), method="DELETE") }}

The default is POST for an explicit URL or new record and PATCH for a persisted record. Nested model sequences infer from the final record, just like forms. Deletion is always explicit. GET and POST render native HTML methods; PUT/PATCH/DELETE render POST plus the corresponding hidden override. GET forms include neither CSRF tokens nor method overrides, preventing tokens in query strings. Unsafe forms include a CSRF token.

Button attributes and form attributes are separate:

{{ button_to("Save", product, id="save-button", form={"id": "save-form", "class": "inline"}) }}

Labels and attributes are escaped; trusted Markup is permitted for labels, not unescaped attributes. Unsupported/executable destination schemes are rejected. Put Turbo data on the form with, for example, button_to("Delete", post, method="DELETE", form={"data": {"turbo_frame": "_top"}}).

Nested forms

Declare accepts_nested_attributes_for() on the parent model, then use fields_for inside form_with. It calls the block once per associated child:

{% call(form) form_with(model=order) %}
  {{ form.label("number") }}
  {{ form.text_field("number") }}
  {% call(item) form.fields_for("line_items") %}
    <fieldset>
      {{ item.label("description") }}
      {{ item.text_field("description") }}
      {{ item.label("quantity") }}
      {{ item.number_field("quantity") }}
      {{ item.label("_destroy") }}
      {{ item.checkbox("_destroy") }}
      {% for message in item.errors.full_messages() %}
        <p role="alert">{{ message }}</p>
      {% endfor %}
    </fieldset>
  {% endcall %}
  {{ form.submit("Save order") }}
{% endcall %}

Fields use names such as order[line_items_attributes][0][quantity], with matching unique label/input IDs. Singular associations omit the collection index. Saved children receive a hidden id; use include_id=False only when you supply the identity yourself. item.model exposes the child and item.errors its validation errors. Raw rejected values and destruction checkboxes survive redisplay. Nested file fields make the outer form multipart, including at deeper nesting levels.

An empty association renders no fields. Build an initial row in the new or edit action when appropriate:

self.order.line_items.new()

Permit the nested fields explicitly; the declaration does not grant permission:

attributes = self.params.expect(
    order=[
        "number",
        ("line_items_attributes", [["id", "description", "quantity", "_destroy"]]),
    ]
)
if self.order.update(**attributes):
    return self.redirect_to(self.order, status=303)
return self.render("edit", status=422)

For a singular association, use a single field list, for example ("profile_attributes", ["id", "name", "_destroy"]). Re-render the submitted object on failure instead of replacing it with a fresh query or appending an extra blank row. See nested attributes for autosave, rejection, deletion, and transaction behavior. Dynamic add/remove JavaScript and automatic nested scaffold generation are not included.

Form values and escaping

Forms show the original submitted scalar input before type conversion, plus assigned writable virtual fields. If there is no pending input, they use saved values. A failed validation therefore redisplays what the user entered, even if type conversion would otherwise lose information.

Authentication secrets, digests, confirmations, and reset tokens are excluded by default. Forms do not use JSON response serialization or evaluate read-only virtual fields such as reset tokens. Re-enter passwords after an unsuccessful submission.

Field names, prefixes, attribute values, input values, and textarea values are escaped. Keep field names and attribute names application-defined. Invalid HTML attribute names raise ValueError. Do not construct field attributes from unfiltered request data.

collection_select() escapes ordinary option labels and prompts. Explicit markupsafe.Markup is accepted for trusted labels and prompts, but option values and other field values are always escaped, even when supplied as Markup.

Form actions accept relative URLs, including protocol-relative URLs, and HTTP(S) URLs. Other schemes and URLs containing control characters raise ValueError. This policy prevents executable schemes; it does not restrict which hosts a form may submit to. Check destinations separately if they come from user input.
