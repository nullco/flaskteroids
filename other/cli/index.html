Using the command line

Run commands from your application directory with bin/flask; no environment activation is needed. You can also use flask in an activated environment or uv run flask.

Use bin/flask --help to list commands, or add --help to a specific command:

bin/flask generate --help
bin/flask db:migrate --help

After reading this guide, you will know how to:

  • Create an application and generate its components.
  • Prepare the database and work in the application shell.
  • Find commands for testing and other framework features.

Generation and setup

flask new my_app
cd my_app
bin/flask run

A new app has its dependencies installed and development database prepared. For a fresh checkout, run bin/setup first.

To generate files without installing, use flask new my_app --skip-install and run bin/setup later. Commit uv.lock so the team shares dependency versions.

For an API instead of server-rendered pages, pass --api when creating the application. Controller and scaffold generators then produce API output. See Building an API for a complete example.

Database preparation

Migrations describe changes to database tables. To create a database if necessary and apply pending migrations:

bin/flask db:prepare

Select another environment with FLASKTEROIDS_ENV:

FLASKTEROIDS_ENV=test bin/flask db:prepare
FLASKTEROIDS_ENV=production bin/flask db:prepare

Preparation does not reset the database or seed records.

Command When to use it
db:prepare Create a database if needed and bring it up to date
db:create Create a database without applying migrations
db:migrate Apply pending migrations to an existing database
db:rollback Undo the most recent migration
db:init Add migration setup to an app that does not have it
db:schema:dump Refresh db/schema.py without changing database data

New applications already include migration setup.

After a migration

Successful migrations regenerate db/schema.py from the selected database. Commit this generated snapshot, but do not edit its columns by hand. Restart servers and workers afterward so they load the new schema.

Review migrations and rollbacks before running them in production: either can delete data. If a command fails, fix the reported problem and retry; the database is left available for inspection. If migrations succeed but writing the snapshot fails, fix the file/access problem and run bin/flask db:schema:dump. A failed snapshot write does not undo database changes.

Startup and connection requirements

Database commands use normal application startup, including initializers. New models can be imported before their tables appear in the snapshot, but an initializer that constructs or queries an unavailable model still fails. There is no separate migration-only startup mode.

For PostgreSQL or MySQL, start the server and configure the connection first. For SQLite, use a file rather than :memory: and ensure its parent directory exists.

Shell

Open an application-aware Python shell:

bin/flask shell

Your models and session are available:

user = User.create(name="Alice")  # Commits before returning.
with User.transaction():
    user.update(name="Alicia")
    User.create(name="Bob")
# Both changes commit at the end of the block.

Standalone save(), create(), update(), and destroy() commit immediately. Inside Model.transaction(), they join the block's transaction. An exception escaping the block rolls the group back; a False save result does not.

Shell exit rolls back unfinished work, not earlier standalone commits. Native SQLAlchemy writes need explicit commit/transaction handling. To discard pending model input, use record.discard_changes() or record.reload(). See model transactions.

Credentials

bin/flask credentials:edit
bin/flask credentials:show
bin/flask credentials:edit --environment production

edit opens encrypted YAML for editing. show prints decrypted secrets: do not copy its output into logs. Environment-specific credentials replace shared ones; they do not merge with them. See encrypted credentials for key setup.

Generators

Use bin/flask generate to create application components. Fields use name:type, such as title:string. See Fields for supported types and modifiers. The examples below use concrete names; replace them with your application's names.

Migration

Generate a migration, review it, then apply it with bin/flask db:migrate. Generating the file alone does not change the database or schema snapshot.

Create a table

bin/flask generate migration CreateProducts name:string!

Use the plural table name after Create, without a Table suffix. New tables include an auto-incrementing id, created_at, and updated_at.

Add columns

bin/flask generate migration AddPriceToProducts price:float

Remove columns

bin/flask generate migration RemovePriceFromProducts price

Drop a table

bin/flask generate migration DropProducts

Model

bin/flask generate model Post title:string author:references

Creates a model class, migration, and tests. References add belongs_to(...) declarations. Columns become available in the schema snapshot after migration.

Controller

bin/flask generate controller Users index show

Creates a controller with the named actions, a view for each, and individual routes. It also creates app/helpers/users_helper.py with a UsersHelper class. Its public methods are available in templates without controller registration. See application helpers.

Resource

bin/flask generate resource Product name:string price:float

Creates a model, migration, empty controller, and resource route. You write the controller actions and views.

Scaffold

bin/flask generate scaffold Product name:string price:float

Creates a model, migration, resource route, controller, and views for the standard index, show, new, edit, create, update, and destroy actions. Apply the migration and restart the server before visiting the resource.

New controller/scaffold page templates use {% extends layout %} for frame-aware layout selection. Scaffold records use underscored dom_id values, and successful updates redirect with 303. Scaffolds remain ordinary full-page CRUD, not inline editors; see Turbo Frames and Streams to add that behavior.

Mailer

bin/flask generate mailer User welcome_email

Creates UserMailer, text and HTML templates, a test, and preview scenarios in test/mailers/previews/user_mailer_preview.py. Supply the base name User, not UserMailer. Browse examples at /flaskteroids/mailers in development. See Preview emails for the walkthrough and Mailers for delivery configuration.

Authentication

bin/flask generate authentication
bin/flask db:migrate

Creates a login and password-management workflow:

  • User with email_address and password_digest.
  • Session with user_id, ip_address, and user_agent.
  • Controllers and views for login and password changes.
  • Password-reset views and mailers.
  • Routes for session and password management.
  • An Authentication concern added to ApplicationController, requiring login by default and exposing the is_authenticated() template helper.

Create an account in the shell; no public sign-up form is generated. To allow a public action, declare skip_before_action("_require_authentication", only=[...]) inside its controller class. Templates can call is_authenticated() on public and protected pages without an extra callback. See the authentication walkthrough.

Work with other components

Each component guide introduces its setup commands as part of a working example:

  • Attribute encryption — generate keys and encrypt attributes.
  • Turbo — install or upgrade the browser runtime.
  • Import maps — pin and maintain JavaScript packages.
  • Rich text — install the editor and its storage tables.
  • Attachments — install file storage.
  • Assets — precompile production files.
  • Middleware — inspect the request stack.

Tests

bin/flask test
bin/flask test:system
bin/flask test test/models/post_test.py

test runs model, integration, job, and mailer tests. test:system runs browser tests. Both accept pytest arguments. See Testing for fixtures, assertions, and browser installation.

Commands outside an application

flask new, flask agent-skills, flask assets:precompile, and flask importmap can run without loading an application. Install Flaskteroids in the Python environment that provides flask.

Outside an application, use a specific command's --help, such as flask new --help. Top-level flask --help attempts application discovery. Other application commands use normal startup, including initializers.
